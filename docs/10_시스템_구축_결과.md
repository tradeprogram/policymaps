### SQLite 스키마 — 28 테이블

### MCP tool 7종 (읽기전용 자문, `execution_allowed:false`)

`search_ordinance` · `get_ordinance` · `similar_regions` · `gap_analysis` · `diffusion_timeline` · `region_profile` · `bill_vote_breakdown`. 판단성 tool 은 `graph.analysis` 계약 함수에 위임하고 실패 시 SQL 폴백. 응답 봉투에 `as_of_date`+`official_url`+`disclaimer`+`stale` 포함. 리소스 3종: `ordinance-graph://status | peers/{sig_cd} | changes?since=`.

### 막힌 것 / 미검증 ⚠️ (설계 결함 아님 — 실키·실응답 필요)

- **실 API 수집(law/ordin/na_bill/na_vote/budget)**: 키 부재로 실데이터 수집 미검증. 무키 상태에서 파티션 격리·오류 계상은 정상 동작 확인. 각 수집기의 파싱 순수함수는 픽스처로 단위 검증됨. 실 200 응답 표본 확보 후 필드 매핑 재확인 필요(각 collector 상단 `확인 필요` 주석).
- **V-World 실경계**: 번들 픽스처는 시도 3 + 시군구 4(합성좌표)만 포함 → 오프라인에선 나머지 regions geometry skip. 실키 시 전국 17 시도 + 226 시군구.
- **2026-07-01 전남광주통합 승계**: 구 지자체(광주 29/전남 46) merged 툼스톤은 적용되나, 통합 신설 지자체 법정동코드 미확정 → 승계 엣지 pending. 코드 확정 시 재적용으로 엣지 생성(합성이벤트로 경로 검증 완료).
- **코드 크로스워크 이름조인분**: `sig_cd=region_cd[:5]` 는 결정적으로 채워지나, `law_org`/`law_sborg`/`lofin_laf_cd` 매핑은 실 API 이름조인 오버라이드가 남음.

> **[2026-08-19 갱신]** 위 ⚠️ 항목 중 실 API 수집·V-World 실경계·`lofin_laf_cd` 크로스워크는 **해소됐다**. 아래 §10.3 참조. 전남광주통합 승계 엣지도 17건 적재됐다.

### `seed-regions` 사용법 — 키 없이 지역 기준정보 적재

`regions` 537 / `region_adjacency` 1,098 / `region_succession` 17 / 인구는 **네트워크 없이** `data/reference/` 번들에서 적재된다. 실키 수집 전에 먼저 돌려야 조례·예산의 `region_id` 매칭이 붙는다.

```bash
cd F:/policy_maps/system
python -m policymap.run init            # 스키마 생성(멱등)
python -m policymap.run seed-regions    # reference/ 실데이터 적재
python -m policymap.run seed-regions --reference-dir /path/to/reference   # 경로 override
python -m policymap.run seed-regions --db /path/to/other.db               # DB override
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--reference-dir` | `data/reference` | 경계 GeoJSON · 법정동코드 · 인구 원본 위치 |
| `--db` | `.env`의 DB 경로 | SQLite 경로 override |

멱등이므로 반복 실행해도 안전하다. 소스는 `run.py::_cmd_seed_regions`.

### 실데이터가 드러낸 구현 이슈(수정 완료)

- **`lofin_laf_cd` 크로스워크**: §10.2에서 "이름조인 오버라이드 남음"으로 남겼던 항목. `laf_cd`(7자리)가 `sig_cd`에서 파생되지 않음을 실측 확인(서울중구 = `1112000`, sig_cd 11140)하고, `ACEXBG` 1회 호출로 받은 243건을 이름 매칭해 채웠다 — **매칭 243/243, 실패 0**. 이로써 `budget_lines.region_id` 1,130행이 전부 연결됐다.
- **`build_similarity` 성능**: sparse 경로가 순수파이썬 O(n²)라 1,087건에서 실행 불가 → `embedding.py`에 scipy CSR 가속 경로 추가(폴백 유지). 두 경로 결과 **완전 일치** 검증 후 2.8초에 완료.
- **`trace_ordinance_diffusion` 의미론**: `enacted_on`이 **현행본 공포일**이라 무필터 곡선은 확산이 아니라 개정 활동을 그린다(1,087건 중 일부개정 635건). `rr_cls_cd` 선택 인자를 추가해 제정본만 분리 가능하게 했다.

> 위 3건 모두 기존 호출부 호환(기본값 유지). CONTRACTS.md 시그니처 갱신 대기 항목: `trace_ordinance_diffusion(rr_cls_cd=)` · `budget_list/collect_budget/search_budget_by_keyword(exe_ymd=, wa_laf_cd=)`.

## 10.4 통합 과정에서 확정·수정한 것

- **인터페이스 일치 확인**: `run.py` 오케스트레이션이 12개 형제 모듈(collectors 4·parsers 4·graph 3·mcp_server)의 CONTRACTS 시그니처를 그대로 호출함을 end-to-end 로 실측. 함수명·인자·테이블명 불일치 없음.
- **CONTRACTS §4.1 tool 이름 정합화**: 계약 초안의 tool 카탈로그(`find_peer_governments` 등, 분석 함수명)와 실제 MCP 표면 이름(`similar_regions` 등 7종)이 달랐다. 서버는 표면 tool → `graph.analysis` 계약 함수로 위임하는 구조로 내부 일관성은 유지되고 33 테스트가 통과하므로, 단일 진실원천인 [CONTRACTS.md §4.1](system/CONTRACTS.md)을 실제 구현(표면 7종 + 위임 매핑)에 맞춰 갱신했다.
- **테스트 산출 stray 정리**: 무키 refresh 검증 중 기본 out 경로에 생성된 `system/data/` 를 제거해 소스 트리를 정결히 유지.
- **선택 의존성 상태**: 통합 환경에 httpx·networkx·shapely·numpy 가 모두 설치되어 가속 경로가 기본 동작하나, 폴백 경로도 테스트로 패리티 검증됨(networkx 부재 시 노드/엣지/Moran I 동일).
